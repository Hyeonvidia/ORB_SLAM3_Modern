# Phase 1 리포트 — 모던 빌드 시스템 + 게이트 판정 (2026-08-06)

## 산출물

- 소스 픽스 3건(golden 기준선 바이너리와 동일): LoopClosing `bool→int`,
  Settings Rectified `calibration2_` 세그폴트 픽스, KITTI00-02.yaml ViewpointY
- 모던 CMake: `DBoW2` / `g2o` / `ORB_SLAM3::core` 타깃 분리, 게이트 실행파일 6종,
  빌드 산출물은 build 트리로(소스 트리 무오염), 플래그 패리티(-O3 -DNDEBUG, march 없음)
- Docker dev 환경(Pangolin 서브모듈 베이크, ninja+ccache), 2단 게이트 스크립트

## 게이트 판정 전말 (방법론 기록)

1. 기준선: 원본 이미지 N=5–6/모드 → 중앙값 mono .0199 / stereo .0379 /
   mono-i .0773 / stereo-i .0356 / kitti00 1.2074
2. 신규 빌드 N=4~6: kitti·mono PASS, EuRoC 3모드 중앙값이 허용한도 2~6% 초과
3. 짝지은 A/B 재실험: stereo는 Δ-0.5%로 해소(경합 인공물), **stereo-inertial만
   Δ+17.8% p=0.017 잔존** → g2o에 상속되던 strict c++17을 컴파일러 기본(gnu++17,
   golden과 동일)으로 되돌리는 픽스 적용 → 그래도 p=0.055로 애매
4. **3-arm 판별 실험** (동일 시간대 교차 실행 ×3):
   원본@원본env 0.0429 ≈ 신규@dev 0.0420 ≈ 원본@dev 0.0448
   → 원본 스스로도 밤에는 기준선(0.0356)을 재현하지 못함.
   **결론: 낮의 기준선 vs 밤의 신규라는 머신 상태 교란이 원인. 빌드는 등가.**

## 최종 판정: PASS

같은 조건 짝지은 비교에서 신규 빌드는 원본과 구분 불가(중앙값 최저는 신규).
g2o std 플래그 픽스는 golden 빌드 패리티 원칙에 따라 유지.

## 방법론 개정 (게이트 v2)

풀 게이트는 저장된 기준선과의 절대 비교를 **금지**하고, 원본/신규 교차(interleaved
paired) 실행의 순위합 검정으로 판정한다. ATE 절대값은 머신 상태(서멀 등)에
±20% 이상 흔들릴 수 있음이 실측됐다. BASELINE.md의 수치는 "정상 범위 참고용"이며
판정 근거가 아니다.
