# P12 계획 초안 (v0, 2026-08-11) — 수명 재설계 · 직렬화 · GTSAM 2차 백엔드

작성 기준: P11-F6(056dfc5) + backend_equiv 수리(198baf0). P11 마무리 게이트(전
플래그 OFF 풀 게이트 + SI 8v8)는 본 초안 작성 시점에 진행 중 — 결과에 따라
§3의 #20 항목을 확정할 것. 근거 문서: docs/P11_RECON.md(이월 분석 원문),
docs/PROJECT_PLAN.md(D1/D5/D7), docs/OWNERSHIP.md(툼스톤 계약),
docs/DIVERGENCES.md(#9/#13/#20).

## 0. 입장 정리 — P11이 이월한 것과 그 이유

| 에픽 | 이월 사유 (P11_RECON) | P12에서 달라지는 것 |
|---|---|---|
| 툼스톤/shared_ptr 수명 재설계 | C-lite는 XL 비용에 회수 0, C-full은 152개 만료 결정에 **오라클 부재**. #20 실증상 XL diff는 게이트로 귀속 불가 | 오라클 인프라(L0)를 페이즈 첫 산출물로 만들어 "부재"를 해소하거나, 못 만들면 근거를 갖고 영구 보류 확정 |
| 직렬화 재설계 | **수명 결정의 하류** — 먼저 하면 두 번 지불 | 수명 결정 확정 후 착수 (순서 강제) |
| GTSAM 2차 백엔드 | 검증 체제 분기(비트 패리티 불가) + 선행 조건 미비(메서드별 등가 하네스, #9/#13 확정) + 엣지 가치 사변적 | 선행 조건을 P12-G0로 명시적 게이트화; #9/#13은 P11-F1/F5로 ON/OFF 계약이 이미 확정됨 |

**세 에픽의 결합 관계** (P11_RECON 이월 표의 지시, 위반 금지):
1. shared_ptr ↔ 직렬화는 **한 결정**이다 (Map/Atlas 아카이브가 포인터 직렬화;
   소유권이 바뀌면 PreSave/PostLoad와 아카이브 포맷이 같이 깨진다).
2. 수명 결정은 **GTSAM ISP 시그니처 동결 전에** 확정한다. 그 전까지 ISP
   인터페이스는 raw 포인터 + pin-set 관례 유지 (안 그러면 이행 팬아웃 ×2 백엔드).
3. 직렬화의 boost 탈피는 GTSAM 4.3의 Boost 제거와 **같은 결정 축**이다 (D7).

따라서 페이즈 내 대순서는 **L(수명) → S(직렬화) → G(GTSAM)** 이되, G의
선행 조건 작업(G0: 프로파일링·하네스 확장·버전 D-기록)은 L과 병렬 가능.

## 1. P12-L — 수명/툼스톤 에픽

### L0. 오라클 인프라 (선행, 규모 M)

C-full이 기각된 유일한 이유는 "152개 만료 결정을 판정할 오라클이 없다"였다.
P12는 이 부재를 페이즈 첫 커밋들로 정면 해소를 시도한다:
- **ASan 게이트 서비스**: dev-tsan과 같은 패턴의 dev-asan compose 서비스 +
  시그니처 대장 (P10-0의 TSAN 대장 방법론 재사용).
- **결정적 리플레이 최소판**: 전체 결정성은 목표가 아니다(멀티스레드 ATE
  비결정성은 수용된 사실). 목표는 **수명 이벤트의 재현 창** — SetBadFlag →
  최후 deref 시점 로깅(BAEpochs 스타일 사이드테이블)으로 "어떤 사이트가
  bad-이후 얼마나 늦게 읽는가"의 실측 분포를 뜬다. 이 분포가 사이트별 만료
  결정의 1차 증거가 된다.
- **Go/No-Go**: L0가 M 규모 안에서 위 두 개를 산출하지 못하면 C-full은
  **영구 보류로 확정**하고(문서화-보류가 아니라 결정), L은 L1/L2만 남긴다.

### L1. 잔여 부분 개선 (P11에서 안 한 것만, 규모 S/M)

- B1 (unique_ptr 큐 커스터디, P11 옵션으로 남았으면): 컴파일러 강제
  커스터디 문서화. 동작 동일 조건이면 착수, 아니면 스킵.
- OWNERSHIP.md의 154→152 사이트 수 교정(P11_RECON이 지적한 stale count) 및
  pin-set 관례 명문화 — G0의 ISP 동결 전 필수.

### L2. 사이트-클래스별 이행 (L0 오라클 확보 시에만, 규모 L~XL, 분할 필수)

152 사이트를 P11_RECON 1a의 패턴 클래스로 나눠, 오라클이 강한 클래스부터:
1. **솔버-로컬** (Sim3Solver/MLPnPsolver, 2 사이트) — 함수 스코프 안에서
   수명이 닫힘, 만료 결정 자명. 파일럿.
2. **직렬화/셧다운 경로** (Map 8 + System 10) — P10-5 조인 사슬 이후 사실상
   단일 스레드. 두 번째로 안전.
3. **Optimizer 로컬 벡터** (62) — pin-set 패턴(진입 시 1회 lock, 내부 raw)
   으로 전환. 핫루프 refcount 비용이 여기 걸림 — 페어드 게이트 필수.
4. **교차 스레드 잔여** (ORBmatcher/Tracking/LocalMapping/LoopClosing/뷰어)
   — 최후, 사이트별 개별 판정.

각 클래스가 독립 커밋+게이트. #20 교훈에 따라 **한 커밋이 게이트로 귀속
가능한 크기를 넘지 않는 것**이 분할 기준이다. 아카이브를 깨는 소유권 변경은
L2에서 하지 않는다 — 그 결정은 S와 함께 내린다(결합 관계 1).

## 2. P12-S — 직렬화 재설계 (수명 결정 하류)

**표적** (P11_RECON 3부 (3)): ① versioning — 현재 전 `serialize()`가
version 인자를 무시하는 위치 기반 포맷이라 필드 하나 추가가 전 .osa를 무언
파손. ② 이중 기록 제거 — boost 포인터 그래프 추적과 수제 Backup-ID 필드가
공존; ID-기반만 남기고 boost 탈피. ③ 이식성 — binary_archive는 크로스
아키텍처 불가(Jetson↔iPhone 세션 교환 차단). ④ 어휘 체크섬은 텍스트 앵커
유지(P11-V 계약).

**형태**: 버전 태그 청크드 바이너리, PreSave/PostLoad의 기존 ID 평탄화 재사용.
규모 M(clean break) / L(레거시 .osa 마이그레이션 로더 포함).

**S-1 확정 (P12-D1, 2026-08-11)**: clean break — 마이그레이션 로더 없음.
기존 .osa 세션 자산은 포기한다(§7 근거 참조).

**순서 강제**: L의 소유권 결정(특히 C-full 여부)이 확정되기 전에 S를
시작하지 않는다. L0가 No-Go로 끝나 툼스톤이 영구 계약이 되면, S는 raw
포인터 전제의 ID-기반 포맷으로 즉시 진행 가능(오히려 단순해짐).

## 3. P12-G — GTSAM 2차 백엔드 (D1의 2차 트랙)

### G0. 선행 조건 게이트 (L과 병렬 가능, 전부 통과 전 G 본작업 착수 금지)

1. **프로파일링 근거**: Orin/iPhone(또는 대리로 arm64 컨테이너)에서 g2o
   최적화 시간이 실제 병목임을 실측. **없으면 G 전체를 다음 페이즈로 재이월**
   — P11_RECON의 "가치 사변적" 판정을 데이터로 뒤집는 것이 G의 존재 조건.
2. **메서드별 등가 하네스 확장** (규모 M): tests/backend_equiv를 제3 변형
   `-DEQUIV_BACKEND=gtsam`으로 확장. 판정은 비트/수치 패리티가 아니라
   **통계 봉투** — 같은 픽스처에서 GT 복구 게이트(이미 analytic GT가 있음)
   + 잔차/수렴 봉투. 방법론 문서를 코드보다 먼저 커밋 (P11 교훈: 검증 체제
   분기는 페이즈 태그의 정합성을 깨므로, 분기 자체를 문서로 선점).
3. **버전 D-기록 — 확정 완료 (P12-D2, 2026-08-11)**: 4.3 대기(Boost
   제거판), PROJECT_PLAN D8로 기록됨. G0 착수 시점에 4.3 릴리스 상태만
   재확인(스테이블 부재 시 프리릴리스 태그 핀 — D8 각주 참조).
4. #9/#13 계약 확정 확인: P11-F1(스케일 야코비안)/F5(LDLT)로 ON/OFF 계약은
   이미 존재. GTSAM 팩터는 **어느 쪽을 정답으로 구현하나** — 원칙: OFF
   (bug-for-bug) 동작을 봉투 기준으로, ON은 fixlevel 속성 테스트를 GTSAM
   변형에도 확장.

### G1. 부분 백엔드 (규모 L)

P11_RECON 3부 (2)의 합성: `GtsamBackend`는 ITrackingOptimizer +
IMappingOptimizer를 네이티브 구현(1-9, 16번 메서드 — CombinedImuFactor,
LinearContainerFactor로 mpcpi 15×15 계약 충족 가능), **GBA/FullInertialBA는
내부 G2oBackend 멤버에 위임**(이중 선언 메서드가 호출자에 따라 다른
최적화기를 타는 문제 차단). System은 두 백엔드를 값으로 소유, config
플래그로 인터페이스 포인터 선택. ISP 시그니처 무변경.

### G2. ILoop 풀 패리티 (규모 XL, 옵션 — 기본은 하지 않음)

Sim3 투영 팩터·4DoF 매니폴드 커스텀 + #13 솔버 절벽 민감성. G1의 실사용
데이터가 필요성을 입증할 때만. P12 기본 범위에서 제외.

## 6. 리스크

1. **오라클 인프라가 M 규모를 초과** → L0 Go/No-Go가 흡수 (에픽이 아니라
   결정으로 끝나는 경로가 설계에 내장됨).
2. **GTSAM 수치가 "제3의 행동"** — g2o 벤더드/업스트림에 이은 세 번째 수치
   프로파일. 봉투 판정의 허용폭 설정이 곧 방법론 리스크 → G0-2에서 방법론
   문서 선행으로 완화.
3. **아카이브 파손의 사용자 영향** — S-1 결정(레거시 호환)에 세션 자산
   정책이 걸림. 결정 전 착수 금지.
4. **페어드 게이트 비용** — L2/G1의 커밋 수 × 라운드당 ~45분. KITTI_SEQ=07
   루틴 게이트로 중간 점검 비용 1/4 절감(경계 판정만 00).
5. **경합 병렬화 유혹** — 게이트 병렬화는 2026-08-09 음성 결과로 기각
   확정. 재논의 금지 (별도 동급 머신 확보 시에만 라운드 단위 분할 재검토).

## 8. 태그 스토리 (초안)

"두 번째 백엔드를 꽂을 수 있는 저장소" — 수명 계약이 결정으로 확정되고
(이행이든 영구 툼스톤이든 근거 포함), 직렬화가 버전드 포맷으로 독립하고,
GTSAM이 통계 봉투 체제에서 부분 백엔드로 검증되는 것. 셋 중 G가 G0에서
재이월되어도 L+S만으로 페이즈는 정합적으로 태그 가능하다 (P11의 툼스톤
이월과 같은 체크포인트 설계).
